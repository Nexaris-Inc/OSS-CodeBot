# スキル・コネクター・コンテキストの内訳

ヘッダーの「ライブラリ」で、スキルとコネクターを管理してチャットに追加します。入力欄左の「＋」からも、ライブラリにある項目をこのチャットに追加・解除できます。追加した項目は入力欄の上にチップで表示し、チップを押すと外せます。追加状態はチャットごとに保持し、チャット保存を有効にしている場合は一緒に保存します。

## スキル

スキルは、`SKILL.md` を1つ含むフォルダです。Claude Codeと同じ形式で、先頭の `---` で囲んだ前置きに `name`（英小文字・数字・ハイフン、64文字以内）と `description`（1024文字以内）を書き、その後に手順を書きます。その他の前置き項目（`allowed-tools` など）は読み飛ばします。

```markdown
---
name: rust-review
description: Rustのコードを所有権・エラー処理・unsafeの観点でレビューする
---
# 手順
1. 所有権と借用の問題を指摘する
```

次の場所から読み込みます。同じ名前のスキルがある場合は、上にある場所を優先します。

| 場所 | 内容 |
|---|---|
| アプリのライブラリ | OS標準のアプリ設定ディレクトリの `skills/`。「取り込む」でここへコピーします |
| 作業フォルダ | チャットの作業フォルダにある `.claude/skills/` |
| ユーザー | `~/.claude/skills/` |

- 取り込むのは `SKILL.md` だけです。同じフォルダのスクリプトや参照ファイルはコピーせず、実行もしません。
- `SKILL.md` は64 KiB以内、本文は20,000文字以内です。シンボリックリンクはたどりません。
- 削除できるのはアプリのライブラリにあるスキルだけです。削除は確認してから実行します。
- 1つのチャットに追加できるスキルは8件までです。

**送信時の扱い**：API・ローカルAIに送るとき、追加したスキルの本文を最初のユーザーメッセージの前に付けます。送信用の会話履歴にはスキルの本文を保存しないため、送信のたびに最新の `SKILL.md` を読み込み直します。見つからないスキルがある場合は送信せず、下書きを残します。入力の文字数上限（`max_input_chars`）はスキルの分だけ広げて判定し、会話全体は `max_context_chars` 以内に制限します。ローカル診断ではスキルを使いません。「AIに作業を相談」でも、相談内容の前にスキルを付けます。

## コネクター（MCP）

コネクターは、標準入出力でやり取りするローカルのMCPサーバーです。名前（英小文字・数字・`-`・`_`、24文字以内）、実行ファイル、引数（1行に1つ）、渡す環境変数名、タイムアウト（1〜300秒）を登録します。登録内容は `gui-preferences.toml` に保存しますが、環境変数の値は保存しません。

- 起動するのは「接続テスト」と、確認済みのツール実行のときだけです。操作ごとに起動し、終わったらプロセスグループごと終了します。
- シェルを使わず、引数をそのまま渡します。作業場所は相談の作業フォルダ、接続テストではチャットの作業フォルダです。
- 環境変数は消去したうえで、PATH・HOME・TEMPなどの基本項目と、登録した変数名だけを渡します。トークンなどを渡す場合は、変数名を登録してCodeBotの起動環境に設定してください。
- 通信は改行区切りのJSON-RPC 2.0で、MCP `2025-06-18` の `initialize` → `notifications/initialized` → `tools/list`／`tools/call` を使います。サーバーからの `ping` には応答し、sampling・roots・elicitationなどの要求は「未対応」と返します。標準エラーは表示しません。
- 応答は1行4 MiB、ツールは128件まで、ツール結果は12,000文字までです。テキスト以外の結果（画像など）は「省略しました」と表示します。
- 1つのチャットに追加できるコネクターは4件まで、登録できるのは32件までです。

**使い方**：コネクターをチャットに追加し、「実行 → AIに作業を相談」を開きます。相談を始めると、まずコネクターに接続してツール一覧を取得し、`mcp__<コネクター名>__<ツール名>` という名前で、組み込みの変更案・コマンドのツールと一緒にAIへ提示します（OpenAI互換・Responses・Claude・Geminiの各形式）。名前が64文字を超えるツールや、名前が重複するツールは提示しません。

AIがコネクターのツールを要求しても、すぐには実行しません。画面にコネクター名・ツール名・引数・起動するプログラム・作業場所・環境変数名・タイムアウトを表示し、「このツールを実行」を押したときだけ実行します。実行中は停止できます。結果をAIへ送る前にも、ほかのツールと同じく別途確認します。拒否・失敗・停止もその旨を結果としてAIへ返せます。コネクターのツールも、1回の相談につき最大4件の操作・8回の通信の上限に数えます。

通常のチャット（ストリーミング表示）ではツールを使わないため、コネクターはAIへ提示しません。

**注意**：コネクターは現在のユーザー権限で動くプログラムです。ファイルの読み書きや外部との通信をする可能性があります。信頼できるサーバーだけを登録し、実行前に引数を確認してください。

## コンテキストの内訳

入力欄の右下に、次の送信に含まれる量を示すセグメントバーと割合を表示します。マウスを乗せると、カテゴリ別の内訳を表示します。

| カテゴリ | 内容 |
|---|---|
| スキル | 追加したスキルの本文と区切り |
| 会話履歴 | 送信用の履歴。「会話履歴を含める」がオフの場合は「履歴送信オフ」と表示し、合計に含めません |
| 添付ファイル | 選択した行範囲と区切り |
| 入力 | 下書きと、解析の種類に応じた依頼文 |

「AIに作業を相談」の画面では、開始前はスキル・ツール定義・相談内容を、開始後はツール定義と、相談の内容・回答・結果の実際の送信量を表示します。コネクターのツール定義は、接続して一覧を取得した後に加わります。

数値は文字数で、設定ファイルの `max_context_chars`（既定64,000文字）に対する割合です。アプリの送信上限の目安であり、モデルのトークン数やコンテキスト長とは一致しません。

## 検証

コアでは、`SKILL.md` の前置き・折り返し記法・不正な値、取り込み・一覧・優先順位・削除、本文の組み立てを確認しています。コネクターは、シェルスクリプトで書いた模擬MCPサーバーを使い、初期化・通知・`ping` への応答、ツール一覧と名前の変換、呼び出し、許可した環境変数だけが渡ること、タイムアウト・中止・エラー応答・起動失敗を確認しています。ツール相談では、コネクターのツール定義の提示、要求が実行されずに返ること、引数の検証を模擬APIで確認しています。GUIでは、スキルが送信用のコピーだけに入ることと、文字数上限の扱いを確認しています。

LinuxのXvfb/X11で、ライブラリ画面、「＋」メニュー、チップ、内訳の表示、接続テスト、模擬APIを使ったコネクターツールの確認・実行・結果の返送を1180×800で操作し、700×540で表示を確認しました。実在のMCPサーバー、Windows/macOSでの起動とプロセス終了は未検証です。CLIからのスキル・コネクター利用には未対応です。
